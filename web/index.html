How it works, in three lines

1. A GitHub Action fetches the project's public history every six hours: PRs, reviews, issues, comments, and the files each merged PR changed.
2. FalkorDB stores it as a graph and computes who knows each area of the code.
3. A Gemini agent answers by choosing graph queries as tools. It may only say what the graph backs, and it cites the PR or issue for each claim.

Public GitHub data only: logins, never emails or names. Built for Graph Hacks (FalkorDB × WeMakeDevs) by Jannet Ekka, with Claude Code as the coding assistant.
